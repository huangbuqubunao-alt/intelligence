# 当前 Goal 的模型可配置原则（用户补充决定）

2026-10-24 用户明确：云端和本地模型应可配置，产品框架固定，适配不同用户的模型；不满足要求时给出提示。此前也明确允许低内存且符合要求的本地模型，但不允许大规模重新开发。

## 产品判断

接受此原则。导入、字幕、摘要、Evidence、提炼、保存、主题、取消和备份恢复是一套固定业务链路。供应方、服务地址、模型/版本、上下文及输出配置属于模型适配边界，不能为每一个新模型复制业务流程或继续向各层散落模型名称判断。

可配置不等于已经验证，也不等于自动获得云端授权。模型不存在、连接失败、接口/输出格式不兼容、资源/上下文不足、尚未验证、实测质量失败必须区分；未做质量验收不能断言“性能差”。前端应呈现具体原因和可执行的设置/切换/重试/取消操作。原文、已经完成的字幕/摘要及历史Evidence不随模型不可用而失效。

模型变更只影响新执行。每个执行冻结实际模型、输入、授权、预算、配置与证据关联；旧任务和备份按原绑定解释，不能因全局设置变化重新运行或改写历史。云端仍需要原有授权、预算和费用保护，不自动付费回退。

## 最小实施约束

DIRECT复用已有AppSettings/local_analysis配置、InstalledCandidate/catalog、Provider adapter、runtime binding及资格缓存；收敛到集中模型描述/适配入口，让业务模块读取同一绑定。保留既有精确历史resolver/旧profile字节，不用放宽校验来冒充通用架构。

先完成当前b6adac2独立审查/整合与全量回归。小模型先独立一次原英文首例诊断，验证有质量希望后才做有限描述适配；诊断不是生产资格，不改业务持久化/Schema/正式配置，不新建框架，不为每个模型复制整套生命周期。必须保留原YT10、LOCAL8、长12和首次真实失败即停规则；新增模型从零获得它自己的实际容量及语义证明。

如最小方案仍要求大范围重写业务流程，拒绝该方案并报告，不把本轮变成架构重建。未发布的当前9b精确工程仍是安全兼容基线，不据此声称用户任意模型已可执行。
