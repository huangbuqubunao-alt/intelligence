# ADR-005：采用复用优先的交付策略

## 状态

Accepted

## 日期

2026-07-14

## 批准记录

产品负责人在主控对话中明确要求：

```text
我不希望我的产品对于已有的东西从0开始做，能复用的直接用了……整体怎么做用不用你自己把控。
```

该授权允许主控在已批准产品范围内决定“直接复用、适配复用、仅参考或拒绝”，但不取消依赖、密钥、云调用、真实 Vault、Cookie、系统工具和许可证等既有审批门禁。

## 背景

本产品涉及 YouTube 发现、字幕、转写、模型调用、SQLite 和 Obsidian。大量底层能力已有成熟实现；从零重写页面解析、challenge solver、模型 SDK 或模板引擎会增加维护风险。另一方面，直接拼装完整第三方应用会绕过本项目已经批准的领域契约、状态机、隐私和幂等要求。

因此采用“成熟组件复用 + 项目特有编排自建”的组合方式：外部组件负责通用能力，本项目只拥有配置、领域契约、状态恢复、策略、审计和安全写入。

## 决策

### R-01：默认复用顺序

每张任务按以下顺序评估，不得默认从零实现：

1. Python 标准库和操作系统稳定能力。
2. 已批准、官方维护且可锁定版本的库、SDK 或 CLI。
3. 许可证兼容、边界清晰的开源组件或小型模块。
4. 经过来源标注的算法、测试夹具、错误映射和交互模式。
5. 只有前述方案不能满足批准契约时，才编写项目专用实现。

### R-02：四级复用结论

每个候选只能落入一个明确等级：

- `DIRECT`：作为锁定依赖，通过本项目 Adapter 使用。
- `ADAPT`：选择性移植小段 MIT/Apache/兼容代码或测试思想，改造成项目契约，并保留来源和许可证要求。
- `REFERENCE`：只借鉴接口、测试矩阵、模板或用户体验，不复制代码。
- `REJECT/DEFER`：因许可证、维护、安全、云依赖、架构冲突或范围不符而拒绝或延期。

完整第三方应用不得未经评估直接 vendor、fork 后嵌入或成为核心状态所有者。

### R-03：复用准入检查

直接或适配复用前必须检查并记录：

- 许可证及 NOTICE/归属要求。
- 最近维护、发布和已知缺陷。
- Python/Apple Silicon/当前工具链兼容性。
- 新增直接与传递依赖、二进制、模型和系统工具。
- 网络、账号、密钥、Cookie、付费、数据外发和遥测。
- 是否禁用 TLS、吞异常、直接写真实 Vault 或绕过路径边界。
- 能否通过 Adapter/Fake 隔离并以离线测试验证。

任何一项触及红线，必须保留原有任务级具体审批，不得用“复用优先”作为绕过理由。

### R-04：架构所有权

第三方组件可以拥有通用能力，但不得拥有以下本项目核心语义：

- `domain.py` 中的公共对象和状态枚举。
- ADR-003 的 SQLite Schema、Job 租约与恢复。
- 云端开关、成本和隐私策略。
- Obsidian 路径边界、原子 upsert 和用户编辑区保留。
- Pipeline 编排、幂等键、审计和任务状态。

所有外部能力必须位于 Provider/Adapter 边界后；更换组件不得改变核心契约。

### R-05：代码来源与许可证证据

- `DIRECT` 依赖通过 `pyproject.toml`/`uv.lock` 记录名称和版本。
- `ADAPT` 如复制或实质改写代码，提交中必须注明原仓库、固定 commit、许可证和修改说明；需要保留版权头或 NOTICE 时一并提交。
- 只借鉴通用思想时记录为 `REFERENCE`，不得声称复制代码。
- 无明确许可证的代码不得复制；搜索摘要、博客片段或截图不能作为代码来源。

### R-06：安全和本地优先否决项

V1 默认拒绝直接复用以下组件：

- 要求未批准的远程 API、账号、Cookie、浏览器登录态或付费额度。
- 自动把密钥写入 shell、配置或非批准 secret store。
- 禁用 TLS 校验、记录原始响应/字幕全文或访问真实 Vault。
- 运行时下载未锁定代码、插件或 remote components。
- 要求未批准的系统级安装、常驻服务或广泛文件权限。

除非产品负责人通过新的任务级授权或 ADR 明确改变边界。

### R-07：任务和审查证据

每个 Implementer 包必须包含一行 `Reuse decision`，列出 `DIRECT/ADAPT/REFERENCE/REJECT` 及来源。交接报告必须说明：

- 实际复用了什么及固定版本/commit。
- 为什么没有复用被评估但拒绝的候选。
- 许可证与归属是否满足。
- Fake/离线测试如何证明 Adapter 可替换。

Reviewer 必须把依赖扩张、许可证遗漏、来源不明复制和绕过边界列入范围审查。

### R-08：主控决策权与升级条件

产品负责人授权主控在既定产品范围和已批准依赖内选择复用方式，无需为每个普通实现细节重复询问。以下情况仍必须升级：

- 新增/升级生产依赖、修改锁文件或安装系统工具。
- 复制许可证义务不明确的代码或引入 GPL/AGPL 等影响分发的许可。
- 引入远程服务、密钥、Cookie、付费、数据外发或真实 Vault 写入。
- 候选要求改变公共领域契约、Schema、状态机或 MVP 范围。

## 当前落地

- `yt-dlp[default,deno]`：`DIRECT`，由 TASK-004 Adapter 隔离。
- Python `sqlite3`：`DIRECT`，由 TASK-003 Repository 隔离。
- 附件中的 video skill/yt2md：主要为 `ADAPT/REFERENCE`，不整套嵌入。
- TranscriptAPI 型 youtube-skills：V1 `REJECT`，避免远程账号、密钥和付费依赖。
- 详细证据和后续复核日期见 `docs/REUSE_REGISTER.md`。

## 后果

- 实现者必须先证明“为什么复用或为什么自建”，减少重复造轮子。
- 项目仍保留自己的领域、状态、恢复和隐私语义，不被第三方应用架构绑死。
- 复用候选会随版本和维护状态变化；每个首次落地任务必须重新核实，不把 2026-07-14 的调研当作永久事实。
- 本 ADR 本身不授权任何尚未批准的依赖、网络服务、系统安装、密钥或真实数据访问。
