# YouTube Intelligence Agent 实施路线图

- 版本：V1.3 + Phase 2 Proposed Addendum
- 状态：`APPROVED`
- 任务入口：`tasks/README.md`
- 协作协议：`docs/COLLABORATION.md`

## 1. 执行原则

- 本路线图只分配工作，不代表授权实现红线事项。
- 每次只领取一张任务卡；任务卡应在一个专注会话内完成。
- 未满足依赖和审批门禁时不得提前实现。
- 每张任务卡必须保留测试/检查证据并复核 Diff。
- 如果实现与规格冲突，先停下并更新/审批规格，不能让代码反向定义需求。
- 按 ADR-005 先做复用评估：成熟组件承担通用能力，本项目只实现领域、状态、策略、恢复和安全控制面。
- `docs/REUSE_REGISTER.md` 是候选事实来源；新依赖、代码适配和许可证义务仍遵守任务级审批。

## 2. 角色

| 角色 | 职责 |
|---|---|
| 产品负责人（PO） | 决定范围、默认行为、成本和隐私边界 |
| 技术负责人（TL） | 审批接口、Schema、依赖和跨任务设计 |
| 实现 Agent | 仅实现已领取任务卡的范围 |
| QA Agent | 验收任务证据、回归和端到端场景 |
| 安全/隐私 Reviewer | 检查密钥、路径、日志和云端数据边界 |

同一人可兼任多个角色，但审批人不应只依据实现者的自述关闭高风险任务。

## 4. 阶段计划

### Phase 0：审批与基础

- `TASK-000`：关闭 V1 开工决策。
- `TASK-001`：建立最小工程脚手架与质量门禁。
- `TASK-002`：建立配置和领域契约。
- `TASK-003`：建立 SQLite 状态、任务与产物索引。

#### Checkpoint A：基础可用

- PRD 和 System Design 已审批。
- 依赖/锁文件变更已单独批准。
- 配置可校验，SQLite 可初始化和迁移。
- 单元测试、Lint、类型检查均可通过。

### Phase 1：本地知识采集主链

- `TASK-004`：完成频道发现与元数据切片。
- `TASK-005`：完成字幕优先级和规范文本切片。
- `TASK-005A`：冻结本地 Whisper/Ollama 复用前共享的配置、领域、评分摘要和 Artifact
  清理契约；不实现 Provider、不安装依赖或模型。
- `TASK-006`：完成无字幕时的本地转写切片。
- `TASK-007`：完成本地评分切片。

#### Checkpoint B：完全本地闭环

- 能从固定夹具发现新视频、得到文本并评分。
- 人工/自动/Whisper 三条路径可验证。
- 重复输入不重复下载、转写或评分。
- 云端功能关闭时不发生任何云端调用。

### Phase 2：知识产出与恢复

- `TASK-008A`（Proposed）：冻结云分析最小化输入、完成/跳过结果、配置和依赖基线。
- `TASK-009A`（Proposed）：冻结 KnowledgeSink/NoteRef 和 Jinja2 依赖基线。
- `TASK-008`：完成可选深度分析。
- `TASK-009`：完成 Obsidian 视频笔记 upsert。
- `TASK-010`：完成端到端状态编排、重试和断点恢复。
- `TASK-011`：完成周报。

#### Checkpoint C：产品闭环

- 低价值路径完成 SQLite/产物索引，高价值路径完成 Obsidian 笔记。
- 失败注入后可恢复且不重复昂贵调用。
- 笔记更新不覆盖用户的 `我的思考`。
- 同一周重复生成不产生重复周报。

### Phase 3：可运维与发布

- `TASK-012`：完成 CLI、doctor、结构化日志和 launchd 样例。
- `TASK-013`：完成离线端到端矩阵和一次受控真实冒烟验收。
- `TASK-014`：完成安装、运行、恢复和发布清单。

#### Checkpoint D：MVP 完成

- PRD 第 10 节的全部验收标准有外部证据。
- 默认测试不依赖网络、真实 Vault 或真实云端密钥。
- 安全/隐私 Reviewer 确认仓库和日志无敏感信息。
- PO 和 TL 人工确认后才标记 V1 完成。

### 5.1 调度输出格式

主控每轮都给出以下三栏，用户启动执行会话后可立即回到主控继续领取其他工作：

| 分组 | 含义 |
|---|---|
| 立即启动 | 当前关键路径上的实现、审查或整合会话 |
| 可并行启动 | 依赖已满足的独立 worktree 任务，或不写仓库的只读 Preflight |
| 等待依赖 | 尚不能安全开始的任务及其阻塞项 |

只读 Preflight 不占写入型 WIP，但默认最多同时运行 2 个，避免产生大量会过期的分析。它不得生成代码、提交或公共任务状态变更。

## 6. 任务领取与完成规则

1. 主控对话确认依赖和审批，将任务设为 `READY`，指定实现者、Reviewer、基线、worktree 和分支。
2. 主控对话把已领取任务设为 `IN_PROGRESS`；实现者不直接修改公共任务状态。
3. 实现者只修改任务卡列出的文件；需要扩展范围时停止并回到 TL/PO。
4. 实现者填写 `handoffs/TASK-<id>.md`、提交 commit 并报告 SHA；主控对话设为 `IN_REVIEW`。
5. 独立 Reviewer 复核验收、测试证据和 Diff；失败则退回 `IN_PROGRESS` 或 `BLOCKED`。
6. Reviewer 通过后仍需主控验收，设为 `ACCEPTED`；Integrator 整合并通过主线检查后才设为 `DONE`。

## 7. 风险优先级

优先验证以下高风险点：

1. Apple Silicon 上 Whisper 的可安装性、速度和内存。
2. YouTube 字幕/元数据获取在固定样例上的稳定性。
3. SQLite 与文件产物的恢复一致性。
4. Obsidian 用户编辑区在 upsert 时不被覆盖。
5. LLM 结构化输出在不同 Provider 下可稳定验证。

如同一失败连续出现两次，停止重复相同方案，保留命令、错误行、相关文件和已尝试方法，交由 TL 决策。

## 8. 变更与升级

- 新增 V2 数据源前先建立独立 PRD，不进入本路线图。
- 任何任务新增生产依赖、修改 Schema、启用真实云调用或写入真实 Vault，都必须获得对应审批。
- 路线图有新增/删除任务时，同步更新 `tasks/README.md` 的状态表和依赖图。
