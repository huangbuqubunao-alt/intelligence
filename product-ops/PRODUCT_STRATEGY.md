# 产品战略与定位（Product Strategy）

- **更新日期**：2026-11-23
- **当前生命周期阶段**：**内部自主迭代与产品完善阶段**（`PUBLIC_BETA` · Apache-2.0，现阶段不招募、不触达真实外部用户）

---

## 1. 产品核心定位

> **一句话定位**：面向双语研究者与深度知识工作者的 **本地优先、可核回原话、敢诚实拒答** 多源研究工作台——把 **YouTube 英文原讲 + B 站中文解析 + 本地 Markdown 笔记** 放进同一个本机 SQLite 证据库，支持跨源原话对照问答与零幻觉拒答，最终带走离开应用后依然能点击跳回原片对应秒数的 **Obsidian Markdown 研究资产**。

---

## 2. 目标客群（ICP 聚焦假设）

### 首要楔子客群（Primary Wedge ICP）`[基于公开社区痛点的定位选择，待未来授权真人试验验证]`
- **角色**：长期使用 **Obsidian / 本地 Markdown 笔记库** 的中文技术研究者、AI 产品经理、深度区创作者与一线工程师。
- **核心痛点**：在做一个跨语种技术或产品调研时，常同时参考 YouTube 英文原讲、B 站中文拆解及本地 `.md` 读书笔记；通用云端总结工具要么不支持 B 站及原生 Obsidian 输出、要么离开平台后时间戳失活、要么在检索不到依据时用训练常识“盲猜硬答”。

### 次要拓展客群（Secondary，留存验证前不单独扩张功能）
- 数据不可出境的独立咨询顾问、金融/法务与企业研发小组（依赖本机 Ollama 或 BYOK 隔离）。

## 3. 核心差异化壁垒（为什么用户会选 Intelligence，而不是 6.8 万星通用 RAG 或免费大厂）

| 能力维度 | Google NotebookLM | 国内音视频 SaaS（BibiGPT/ima） | 通用开源 RAG（Open Notebook/AnythingLLM） | **Intelligence 差异化切口（已实现）** |
|---|---|---|---|---|
| **YouTube + B 站 + Markdown 同库对照** | 强于 PDF/YT，无原生 B 站适配与双向 Obsidian 出口 | 偏向“单条视频速览”，缺多视频 + 本地 `.md` 严密比对 | 重 Docker 自托管或通用 PDF 切片，缺 B 站与短视频噪音折叠 | **原生把 YouTube (`TIME_RANGE`) + B 站 (`BV`) + 本地 `.md` (`TEXT_RANGE`) 锁入统一 SQLite 证据链对比** |
| **反幻觉透明边界（Fail-Closed）** | 社区高频反馈复杂材料会漏入外部常识或指错引用 | 一键总结为主，极少暴露“证据不足拒答态” | 召回弱时常凑答案，缺少硬性 `evidence_id` 拒答门禁 | **无后端真实匹配 `evidence_id` 一律拒答 (`REFUSED_INSUFFICIENT_EVIDENCE`)，仅将相似片段放入独立“仅供参考”区** |
| **带原片跳转的离线可用导出** | 脱离其网页端后无法保留可点击毫秒级原片定位 | 导出常需高价 Pro，或偏文本排版不带严谨 `ev:` 溯源 | 多为纯摘要文本 | **导出 Markdown 与纯文本直接附带 `https://...?t=` 外链、段落范围 `P#(start–end)` 与 `ev:` 指纹** |
| **本地隐私与零静默花费** | 数据传 Google 云端，受 5 小时算力滚池约束 | 上传厂商云端，Plus `$19.8/月` · Pro `$34.8/月` | 门槛在 Docker 编排与多服务调试 | **一行 `uv run youtube-intel start` 本地启动、Zero-Telemetry、后台禁用云花费、BYOK 日上限与 Keychain 隔离** |

## 4. 明确的反目标（内部完善期坚决不做）

为严格践行“**不以功能多寡论英雄，只以核心用户价值、质量确定性与证据为锚**”，未来 30 天内坚决**不做**：
1. **不做** V2 全网链接爬虫（X、小红书、微信公众号、泛网页与播客抓站），避免分散主链路稳定性精力。
2. **不做** 多模型自动 `hybrid` 无感路由或后台悄悄调云端接口，死守零静默扣费承诺。
3. **不做** 托管 SaaS 多租户账号系统、计费后台或花哨双人播客音频克隆。
4. **不做** 任何面向真实用户的公测招募、社群发帖或用户访谈（严格遵守内部阶段边界直至创始人明确授权进入下一阶段）。

## 5. 当前内部阶段的核心战略目标（30 天）

1. **消灭最后一公里隐形使用摩擦**：通过 AI 多角色模拟、空白冷启动巡检和真实浏览器端到端回归，持续扫平首次使用、空状态、报错可读性、响应式触控、导出完整性上的体验断层。
2. **保持工程基线零退步**：任意迭代必须满足 `ruff`、`mypy`、11 组 `pytest`、全量 `vitest` 与 Chromium 实机验证同步全绿，不引入虚假状态、不留死链路。
3. **打磨好可随时交接的商业化假设与增长资产**：将定价经济账（`COMMERCIALIZATION.md`）、内部运营文案包（`OPS_ASSETS.md`）及风险清零基线准备齐全，待创始人裁决仓库形态（`FD-005`）并按节奏决定何时迈入真实用户验证阶段。
